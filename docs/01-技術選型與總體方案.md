# NovaBoot（暫定名）技術選型與總體方案

> 企業級 Web 應用基礎框架 · 開源社區項目
> 文檔版本 v0.1 · 2026-10-31 · 狀態：待評審

---

## 1. 項目定位

### 1.1 一句話定位

一套開箱即用的開源企業級 Web 應用基礎框架：內置用戶、角色、選單（RBAC 權限體系）等後台系統標配能力，前後端分離，讓開發者把精力放在業務上。

### 1.2 目標與非目標

**目標（v1.0 範圍）**

- 開箱即用的 RBAC 權限體系：用戶 / 角色 / 選單 / 部門 / 崗位 / 資料權限
- 後台系統標配模組：字典、參數配置、操作日誌、登入日誌、檔案管理、任務調度、通知公告、線上用戶
- 代碼生成器：業務表一鍵生成前後端 CRUD 代碼與選單 SQL
- 模組化架構，二次開發友好；MIT 寬鬆協議

**非目標（首年不做，保留演進路徑）**

- 不以微服務作為首發形態（模組邊界即未來的服務邊界）
- 不首發 SaaS 多租戶（納入 M3 規劃）
- 不綁定特定雲廠商、不內置業務報表/低代碼引擎

### 1.3 對標項目與差異化

| 對標項目 | 技術棧 | 特點 | 可借鑒 |
|---|---|---|---|
| RuoYi | Spring Boot + Vue | 事實標準、用戶量最大 | 功能清單、代碼生成思路 |
| JeecgBoot | Spring Boot + Vue3 + AntD | 低代碼能力強 | 表單/報表生態（非首發範圍） |
| yudao（芋道） | Spring Boot + Vue3 | 模組最全、多租戶、AI 模組 | starter 化的模組劃分 |
| gin-vue-admin | Go + Vue | 部署輕量 | — |
| soybean-admin | NestJS + Vue3 | 前端工程現代化 | 前端 monorepo 結構 |

**差異化（回答「為什麼不用 RuoYi」）**

1. **架構乾淨**：模組化單體 + Starter 插件機制，平台能力與業務模組邊界清晰、可拆卸，避免「全家桶麵條式」二開
2. **工程現代**：前端 pnpm monorepo、TypeScript 全量、原子化樣式、單測/CI 齊備，而非腳本堆疊
3. **版本新、無歷史包袱**：直接基於 JDK 25 LTS + Spring Boot 4.x，不背 2.x/3.x 遺留代碼
4. **AI 時代賣點**：預留 LLM 網關 / AI 應用 Starter（對話、RAG 基座、AI 輔助代碼生成），這是 2026 年後台框架的加分項
5. **交付體驗**：VitePress 文檔站 + 在線 Demo + Docker Compose 一鍵啟動

### 1.4 開源策略

- 協議：**MIT**（寬鬆，利於商用採用與社區傳播）
- 倉庫：GitHub 單倉 monorepo（前後端同倉，版本同步發佈）
- 社區：CONTRIBUTING 指南、Issue/PR 模板、good first issue 標籤、Roadmap 公開
- 命名：暫定 **NovaBoot**（最終名稱待定，目錄/包名可全局替換）

## 2. 總體架構

### 2.1 架構風格：模組化單體（Modular Monolith）

- 單體部署、模組強隔離：以 Maven 多模組在編譯期強制模組邊界，平台能力（security/web/cache/storage/log）以 Starter 形式提供，業務模組按需引入
- 演進路徑明確：M4 可選升級微服務形態（Spring Cloud Alibaba / K8s），模組邊界直接映射服務邊界，避免推倒重來

### 2.2 部署拓撲（v1）

```
瀏覽器 ──► Nginx（靜態資源 + 反向代理）
              │
              ▼
        nova-server-admin（Spring Boot 單體，可多實例 + LB）
              │
              ├── MySQL 8.4（主庫；Flyway 版本化遷移）
              └── Redis 8（會話 / 緩存 / 驗證碼 / 分散式鎖 / 限流）
```

### 2.3 倉庫結構

```
nova-boot/
├─ nova-dependencies/       # Maven BOM，統一三方依賴版本
├─ nova-common/             # 通用包：統一響應、異常、常量、工具類
├─ nova-framework/          # 技術組件 Starter：安全、緩存、日誌、存儲、Web 配置
├─ nova-module-system/      # 系統模組：用戶/角色/選單/部門/崗位/字典/日誌/檔案...
├─ nova-module-generator/   # 代碼生成器
├─ nova-module-job/         # 任務調度（Quartz）
├─ nova-server-admin/       # 啟動器（唯一可執行打包單元）
├─ web/                     # 前端 pnpm monorepo
│  ├─ apps/admin/           # 管理端應用（Vite + Vue3）
│  └─ packages/{ui,utils,api-client,hooks}/   # 可復用包，為插件生態打基礎
├─ docs/                    # VitePress 文檔站源碼
└─ deploy/                  # Dockerfile、docker-compose.yml、SQL 腳本
```

## 3. 技術選型

### 3.1 選型原則

1. 主流成熟優先於新潮；2. 中文文檔與社區活躍度；3. 寬鬆許可協議；4. 目標用戶易上手；5. 可替換性（平台接口抽象，不鎖死具體實現）

> 版本基準日：2026-10-31（版本數據已核對 endoflife.date）。全部依賴由 `nova-dependencies` BOM 統一鎖定，啟動前跑一次依賴相容性矩陣驗證。

### 3.2 後端語言 / 框架比較

| 候選 | 同類框架先例 | 性能 | 部署 | 國內社區接受度 | 結論 |
|---|---|---|---|---|---|
| **Java + Spring Boot 4** | ★★★（RuoYi / Jeecg / yudao 同路線） | 中 | 中（JVM） | 極高 | ✅ **主選** |
| Go + Gin | ★★（gin-vue-admin） | 高 | 極佳（單二進制） | 高 | 備選 |
| Node + NestJS | ★★（soybean 系） | 中 | 好 | 中 | 備選 |
| Python + FastAPI | ★ | 低-中 | 好 | 中 | 不選 |

選 Java 的理由：本品類的目標用戶（企業後台開發者）主流棧就是 Java；同類成熟先例最多，功能設計有據可依；ORM、權限、調度、工作流、報表等企業組件生態最全。Go/NestJS 路線留作文檔中的對照說明，若社區反饋強烈可由社區 fork 推進。

### 3.3 後端清單

| 類別 | 選型 | 說明 |
|---|---|---|
| JDK | **25 LTS**（Temurin） | Spring Boot 4.1 支持 Java 17–26，取當前 LTS |
| 核心框架 | **Spring Boot 4.1.x**（當前 4.1.2） | 3.5 開源維護已於 2026-06 結束，新項目不建議再入 3.x |
| 認證授權 | **Sa-Token** | 輕量、RBAC/註解鑑權/踢人下線開箱即用；啟動前驗證其對 Boot 4 的適配版本，若滯後則退 Spring Security 7 |
| ORM | **MyBatis-Plus** | 國內主流、CRUD 效率高；同樣需確認 Boot 4 適配，備選 Spring Data JPA / MyBatis-Flex |
| 資料庫 | **MySQL 8.4 LTS**（主）+ PostgreSQL 17+（適配層） | 標準 SQL 優先，避免 MySQL 私有語法滲透 |
| 資料庫遷移 | **Flyway** | 版本化 DDL/初始化數據，棄用「手工執行 SQL 腳本」模式 |
| 緩存/會話 | **Redis 8**（兼容 Valkey）+ Redisson | 會話、驗證碼、緩存、分散式鎖、接口限流 |
| 介面文檔 | SpringDoc OpenAPI 3 + Knife4j | |
| 參數校驗 | Jakarta Validation | |
| 對象映射 | MapStruct | 編譯期生成，無反射開銷 |
| 工具庫 | Hutool、Lombok | |
| Excel 匯入匯出 | FastExcel（EasyExcel 後繼） | |
| 代碼生成模板 | FreeMarker | |
| 任務調度 | Quartz（M1 內置） | M3 評估 Snail Job / XXL-JOB 分佈式調度 Starter |
| 監控 | Actuator + Micrometer（Prometheus + Grafana 可選接入） | |
| 測試 | JUnit 5 + Mockito + Testcontainers | 核心鏈路（登入、權限）必須有自動化測試 |

### 3.4 前端清單

| 類別 | 選型 |
|---|---|
| 框架 | Vue 3.5+（Composition API + `<script setup>`） |
| 語言 | TypeScript 5（全量） |
| 構建 | Vite 7+ |
| 狀態管理 | Pinia 3 |
| 路由 | Vue Router 4（後端選單 → 動態註冊路由） |
| 組件庫 | Element Plus |
| 樣式 | UnoCSS（原子化、按需） |
| HTTP | Axios（統一封裝：Token 注入、錯誤碼、取消重複請求） |
| 工具庫 | VueUse |
| 圖表 | ECharts |
| 包管理 | pnpm monorepo（workspace） |
| 代碼規範 | ESLint 9+ + Prettier + Husky + commitlint（Conventional Commits） |
| 測試 | Vitest（單測）+ Playwright（登入/權限等核心鏈路 E2E） |
| Node | 24 LTS（26 已於 2026-10-28 轉 LTS，可選） |

為什麼 Vue 而不是 React：本品类国内主流是 Vue + Element Plus，与目标用户（企业后台开发者）匹配度最高；React + AntD 路线留给社区生态，不进首发范围。

### 3.5 工程與基礎設施

- 版本管理：Git / GitHub，`main` + feature 分支流，Conventional Commits + 自動 CHANGELOG
- CI/CD：GitHub Actions —— 後端：build + test + Docker 鏡像；前端：lint + typecheck + build；發佈到 GHCR / Docker Hub
- 本地環境：`docker compose up` 一鍵拉起 MySQL + Redis，後端/前端均可本地直跑
- 文檔：VitePress 文檔站（快速開始、模組開發指南、Starter 開發指南）
- 演示：低成本雲主機掛在線 Demo + 重置腳本

## 4. 核心設計

### 4.1 RBAC 權限模型

- 關係：`用戶 ─n:n─ 角色 ─n:n─ 選單`；`用戶 ─n:1─ 部門（樹）`；崗位作為用戶分組輔助
- 資料權限：角色綁定資料範圍（全部 / 自訂部門 / 本部門 / 本部門及以下 / 僅本人），SQL 層通過攔截器注入過濾條件
- 鑑權三層：
  1. 接口級：後端註解（如 `@SaCheckPermission("system:user:list")`）
  2. 選單級：動態路由按選單樹過濾
  3. 按鈕級：前端權限指令 `v-permission` 控制操作按鈕顯隱

### 4.2 認證與會話

- 帳號密碼 + 行為驗證碼登入 → Sa-Token 簽發 Token，會話存 Redis
- 支持線上用戶查看、強制下線、單端互踢（可配置）；密碼採用 BCrypt 加密存儲，默認管理員首次登入強制改密；登入失敗鎖定策略；登入日誌全量記錄

### 4.3 動態選單與路由

- 選單三類型：目錄 / 選單 / 按鈕（按鈕掛權限字元，不產生路由）
- 後端按角色返回選單樹 → 前端映射組件表動態註冊路由，刷新後可恢復（Token + 路由快取）

### 4.4 通用橫切能力

統一響應體 / 全域異常處理 / 審計欄位自動填充（創建人、更新人、時間）/ 操作日誌註解（AOP）/ 防重複提交與冪等 / 基於 Redis 的接口限流 / 敏感數據脫敏序列化

### 4.5 代碼生成器

讀取 `information_schema` 表元數據 → 在線配置（生成範圍、模板、字段表單類型）→ 生成 後端（entity / mapper / service / controller）+ 前端（api / 列表頁 / 表單）+ 選單 SQL，支持在線預覽與 zip 下載

### 4.6 核心數據表（摘要）

`sys_user` / `sys_role` / `sys_menu` / `sys_dept` / `sys_post` / `sys_user_role` / `sys_role_menu` / `sys_role_dept` / `sys_dict_type` / `sys_dict_data` / `sys_config` / `sys_notice` / `sys_oper_log` / `sys_login_log` / `sys_file_info`

（完整 DDL 隨 Flyway 在 M0 詳設產出，含索引與初始化數據）

## 5. 路線圖

| 里程碑 | 周期 | 內容 | 交付標誌 |
|---|---|---|---|
| **M0 骨架** | 2 週 | 倉庫/CI/規範/骨架；登入登出、驗證碼；用戶/角色/選單 CRUD；動態路由 + 按鈕權限 | 可登入、可配權限的骨架 Demo |
| **M1 系統模組** | 3–4 週 | 部門崗位、字典、參數、通知公告、操作/登入日誌、線上用戶、資料權限、檔案上傳（本地/S3） | 後台標配模組齊全 |
| **M2 效率與交付** | 3–4 週 | 代碼生成器、Excel 匯入匯出、監控接入、Docker 一鍵部署、文檔站、在線 Demo | **v1.0 發佈** |
| **M3 生態擴展** | 持續 | 多租戶、工作流（Flowable 選裝 Starter）、AI Starter（LLM 網關 / RAG）、短信/郵件/支付 Starter、插件機制 | 按模組獨立發版 |
| **M4 演進** | 規劃 | Spring Boot 4.x 小版本跟進、可選微服務形態（Spring Cloud Alibaba）、K8s 部署方案 | 架構升級報告 |

## 6. 風險與對策

| 風險 | 對策 |
|---|---|
| 同質化競爭（RuoYi 等強勢存量項目） | 明確差異化（§1.3）；先做「小而美、架構乾淨」的 v1，靠工程質量與 AI 賣點獲客 |
| Boot 4 生態過渡期組件適配滯後（如 MyBatis-Plus / Sa-Token） | 啟動前做相容性矩陣驗證；BOM 統一鎖版本；每個關鍵組件準備好備選（JPA / Spring Security） |
| 開源長期維護成本 | 模組化降低理解門檻；核心鏈路自動化測試；貢獻者指南與 Issue 模板分流 |
| 安全風險（管理後台是攻擊重點） | 預設安全配置（強密碼策略、登入防爆破）；Dependabot + Trivy 依賴漏洞掃描；發佈前安全自查清單 |
